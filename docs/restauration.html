Restoration

The NAS copy is a Restic repository and can be used for both file recovery and complete repository recovery.

1. Verify the NAS share

findmnt /mnt/restic

The result must show the expected NAS CIFS share.

2. Restore files from a snapshot

sudo restic -r /mnt/restic snapshots
sudo mkdir -p /restore
sudo restic -r /mnt/restic restore ID_DU_SNAPSHOT --target /restore

The restore is placed in /restore, allowing you to verify files before putting them back into production.

3. Complete Restic repository recovery

If the local repository used by rest-server is lost or must be replaced by the NAS mirror, use the dedicated recovery command:

sudo /usr/local/sbin/restic-nas-restore-repository

The command verifies the NAS mount and repository structure, asks for an explicit RESTORE confirmation, stops rest-server, mirrors the NAS repository back to /srv/rest-server/data/, and restarts the container.

4. What the repository recovery restores

The recovery copies the Restic repository itself, including its repository structure, keys, data, indexes and snapshots. Files that exist locally but are absent from the NAS mirror are removed so the local repository matches the NAS copy.

Important Repository recovery restores the Restic repository. It does not reinstall Debian, Docker, rest-server, or other system software. Those components must already be installed or rebuilt separately.
