Restoration

The NAS copy is a Restic repository and can be used for both file recovery and complete repository recovery.

1. Verify the NAS share

findmnt /mnt/restic

The result must show the expected NAS CIFS share.

2. Restore files from a snapshot

sudo restic-nas restore
sudo restic-nas restore /restore SNAPSHOT_ID

The default target is /restore. This lets you verify files before putting them back into production.

3. Complete Restic repository recovery

sudo restic-nas restore-repository

The command verifies the NAS mount and repository structure, asks for an explicit RESTORE confirmation, stops rest-server, mirrors the NAS repository back to /srv/rest-server/data/, and restarts the container.

4. What repository recovery restores

The recovery copies the Restic repository itself, including its structure, keys, data, indexes and snapshots. Files that exist locally but are absent from the NAS mirror are removed so the local repository matches the NAS copy.

Important Repository recovery restores the Restic repository. It does not reinstall Debian, Docker, rest-server, or other system software.
